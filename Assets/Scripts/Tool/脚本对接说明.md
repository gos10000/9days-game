# 脚本对接文档

本文档说明项目四个脚本的职责、对外接口与配置要求，供其他程序 / 其他开发者对接使用。

对应版本：2026-11-01（以当前仓库代码为准，改动代码后请同步更新本文档）

---

## 一、总览

项目当前有四个脚本，分两组，组内互相依赖、组间没有耦合。

**弹弓玩法**

```
Rock        挂在球上    拖拽、发射、与发射者的碰撞忽略
RockReset   挂在球上    按 R 把球复位到弹弓上
```

**场景触发**

```
StartBoxTrigger   挂在触发区    物体进入后加载指定场景
ExitBoxTrigger    挂在触发区    物体进入后退出游戏
```

`RockReset` 运行时通过 `GetComponent<Rock>()` 找到 `Rock`，调用它的 `ResetRock()` 清理状态，两者**必须挂在同一个 GameObject 上**。两个 BoxTrigger 与弹弓玩法没有引用关系。

---

## 二、脚本目录

文件位置与编号对照：

1. `Rock` —— `Assets/Scripts/Rock.cs` —— 球本体：拖拽、发射、碰撞忽略（详见 4.1）
2. `RockReset` —— `Assets/Scripts/Tool/RockReset.cs` —— 球复位：按键回到弹弓（详见 4.2）
3. `StartBoxTrigger` —— `Assets/Scripts/StartBoxTrigger.cs` —— 触发区：加载指定场景（详见 4.3）
4. `ExitBoxTrigger` —— `Assets/Scripts/ExitBoxTrigger.cs` —— 触发区：退出游戏（详见 4.4）

---

## 三、装配结构

`Player1`、`Rock` 已做成 Prefab，位于 `Assets/Prefabs/`：

```
Player1.prefab
├── Player1 根物体  Transform + Rigidbody2D（无 Collider）
├── Body            Transform + SpriteRenderer + Animator + BoxCollider2D
│                   ↑ 刚体沿用父物体 Player1 的，碰撞体在这里
└── Hook            Transform + SpriteRenderer + Rigidbody2D（无 Collider）
                    ↑ SpringJoint2D 的连接锚点

Rock.prefab
└── Rock 根物体     Transform + SpriteRenderer + Rigidbody2D + CircleCollider2D
                    + SpringJoint2D + TrailRenderer + Rock 脚本
                    ↑ joint 连到 Hook
```

## 四、脚本说明

### 4.1 Rock

**挂载位置**：`Rock` 根物体
**必需组件**：`Rigidbody2D`、`Collider2D`、`SpringJoint2D`（除 `rb` 需手动引用外，其余由 `GetComponent` 获取）

#### 公开字段

1. `rb`（Rigidbody2D）—— 球的刚体，**必须手动拖入**
2. `releaseDelay`（float，默认 0.1）—— 松手后多少秒禁用 `SpringJoint2D`（也就是0.1秒后脱离弹弓，时间太长会被拉回来）
3. `crashDelay`（float，默认 0.5）—— 松手后多少秒才开始检测和玩家的碰撞(不然一开始就撞玩家)
4. `launcher`（Transform，分组「发射者」）—— 发射者根物体，**必须指向 `Player1`**（用来避免和该物体的碰撞）

#### 公开方法

`public void ResetRock()` —— 把球的状态恢复到初始，位置为挂钩位置，所以玩家被迫位移后重置还是在玩家身上（位置这一步实际由 `RockReset` 执行，见 4.2）：

1. 清 `isPressed`、清 `isCrashable`
2. 刚体切回 Dynamic，清空线速度与角速度
3. 重新启用 `SpringJoint2D`
4. 重新忽略与发射者的碰撞

**只重置状态，不重置位置**。位置由 `RockReset` 负责。

#### 内部状态

1. `isPressed` —— 是否正在被拖动
2. `isCrashable` —— 发射后经过 `crashDelay` 变为 true，表示可以开始检测分离
3. `isIgnoringLauncher` —— 当前是否处于「忽略发射者碰撞」状态

#### 完整行为流程

1. **Awake**：缓存自身 Collider，调用 `SetIgnoreLauncher(true)`，让球在待命时就与玩家不碰撞
2. **OnMouseDown**：刚体切 Kinematic，`isPressed = true`；此后 `Update` 每帧把 `rb.position` 设为鼠标世界坐标
3. **OnMouseUp**：若 `isPressed` 为 false 直接返回（防止拖拽中被重置后误发射）；否则切回 Dynamic，启动两个协程
4. **Release 协程**：等待 `releaseDelay` 后禁用 `SpringJoint2D` → 球脱离弹弓
5. **Crash 协程**：等待 `crashDelay` 后 `isCrashable = true` → 开始允许检测分离
6. **FixedUpdate**：当 `isIgnoringLauncher && isCrashable` 时，检查自身与发射者所有碰撞体的包围盒是否还重叠
7. **分离判定**：全部不重叠时调用 `SetIgnoreLauncher(false)` 恢复碰撞 → 球反弹回来可以再次撞到玩家

#### 碰撞忽略机制

```csharp
Physics2D.IgnoreCollision(球 Collider, 发射者所有子 Collider, ignore)
```

分离判定只比较 **x / y 两个轴**：

```csharp
static bool Overlaps2D(Bounds a, Bounds b)
{
    return a.min.x < b.max.x && a.max.x > b.min.x &&
           a.min.y < b.max.y && a.max.y > b.min.y;
}
```

**不能用 `Bounds.Intersects`**：它会连 z 轴一起比较，而本场景中球的 `z=-2.78`、玩家 Body 的世界 `z≈0`，z 轴永远不相交，会导致忽略状态被立刻撤销。

#### 对接注意

1. **`launcher` 为空时，整套碰撞忽略逻辑静默失效**（`SetIgnoreLauncher` 第一行 `return`）。`Rock.prefab` 中该字段当前为 `fileID: 0`，必须把 `Player1` 拖进去，否则球会一直把玩家顶开。
2. `GetComponentsInChildren<Collider2D>(true)` 会收集发射者**整个子树**的碰撞体，所以传根物体（`Player1`）即可，不要传 `Body`。
3. 分离判定用包围盒（AABB），对圆形碰撞体略保守：可能比真实分离晚几帧才恢复碰撞，属于可接受误差。
4. `Debug.Log` 会输出 `[rock] IgnoreCollision -> True/False`，排查时看 Console 或 `Editor.log` 即可确认状态切换。

### 4.2 RockReset

**挂载位置**：`Rock`（必须与 `Rock` 同物体）
**必需组件**：`Rigidbody2D`（`[RequireComponent]` 自动补）

#### 公开字段

1. `resetKey`（KeyCode，默认 `R`）—— 触发重置的按键
2. `followJointAnchor`（bool，默认 true）—— 是否复位到弹弓锚点当前位置
3. `resetPoint`（Transform，默认空）—— 指定复位点，优先级最高

#### 公开方法

`public void ResetRock()` —— 立即执行一次重置，可被外部代码直接调用，不必按键。

#### 复位位置的决定顺序

1. `resetPoint` 不为空 → 用它
2. 否则 `followJointAnchor == true` 且 joint 有 `connectedBody` → 用锚点世界坐标
   `joint.connectedBody.transform.TransformPoint(joint.connectedAnchor)`
3. 否则 → 用 `Awake` 时记录的场景初始坐标

#### 执行内容

1. 先恢复刚体类型（Kinematic 状态下写速度会被忽略）
2. `rb.position`、`rb.rotation` 复位
3. 清空 `linearVelocity` / `angularVelocity`
4. 重新启用 `SpringJoint2D`
5. 调用 `Rock.ResetRock()` 清理内部状态

### 4.3 StartBoxTrigger

**挂载位置**：任意带 `Collider2D` 的物体，且必须勾选 `Is Trigger`
**依赖**：`UnityEngine.SceneManagement`

#### 公开字段

1. `targetScene`（string）—— 目标场景名，**不带路径、不带 `.unity` 后缀**

#### 行为

1. `OnTriggerEnter2D`：任意 Collider2D 进入触发区
2. 若 `isLoading` 已为 true，直接返回（防止同一帧重复触发）
3. 置 `isLoading = true`，调用 `SceneManager.LoadScene(targetScene)`

#### 对接注意

1. **`targetScene` 填的场景必须已加入 Build Settings**（`File > Build Settings > Scenes In Build`）。漏加的话编辑器里可能不报错，打包后加载失败或黑屏。
2. **触发器要生效，两个碰撞体里至少有一个挂 `Rigidbody2D`**。纯静态 Collider 之间不会产生触发事件。玩家和球都有刚体，正常情况没问题。
3. `isLoading` 只用于防同一次进入的重复加载；场景切换后脚本随旧场景销毁，不需要手动复位。
4. 没有 tag / layer 过滤，**任何**带 Collider 的物体进入都会触发，包括球。若只想让玩家触发，需自己加判断，例如 `if (!collision.CompareTag("Player")) return;`。
5. 代码里 `using Unity.VisualScripting;` 是未使用的引用，可删，不影响功能。

---

### 4.4 ExitBoxTrigger

**挂载位置**：任意带 `Collider2D` 的物体，且必须勾选 `Is Trigger`
**依赖**：`UnityEngine.SceneManagement`（实际只用到 `Application.Quit`）

#### 公开字段

无。

#### 行为

`OnTriggerEnter2D`：任意 Collider2D 进入即调用 `Application.Quit()`。

#### 对接注意

1. **编辑器里 `Application.Quit()` 不生效**，只在打包后的可执行程序中退出。想在编辑器里测试效果，需要改成：

   ```csharp
   #if UNITY_EDITOR
       UnityEditor.EditorApplication.isPlaying = false;
   #else
       Application.Quit();
   #endif
   ```

   注意 `UnityEditor` 的引用必须包在 `#if UNITY_EDITOR` 里，否则打包会编译失败。

2. 没有任何过滤条件，**球飞进去也会退出游戏**。作为「出口」区域使用时留意。
3. 没有防重复触发，但进程会直接结束，通常不需要。
4. `Application.Quit()` 在 WebGL 平台无效，需要另外处理。

## 五、对接清单

### 5.1 弹弓玩法

Inspector 里必须完成这三项配置（Prefab 与场景实例都要检查）：

1. `Rock.prefab` 上 `Rock` 组件的 `rb` → `Rock` 自己的 `Rigidbody2D`（当前已赋值）
2. `Rock.prefab` 上 `Rock` 组件的 `launcher` → `Player1` 根物体（**当前为空，必须补**）
3. `Rock.prefab` 的 `SpringJoint2D.Connected Rigidbody` → `Player1` 下的 `Hook` 的刚体

> 如果 Prefab 实例已经摆进场景，改完 Prefab 后要确认场景实例同步（Inspector 中未标 `Override` 的字段才会跟随 Prefab）。

外部程序可用的入口只有两个：

1. `Rock.ResetRock()` —— 只清状态，不动位置
2. `RockReset.ResetRock()` —— 完整复位（含位置）

其余行为（拖拽、发射）都由鼠标事件驱动，没有对外暴露的「发射」方法。若要程序化发射，可在 `Rock` 中新增：

```csharp
public void Launch(Vector2 velocity)
{
    isPressed = false;
    rb.bodyType = RigidbodyType2D.Dynamic;
    rb.linearVelocity = velocity;
    StartCoroutine(Release());
    StartCoroutine(Crash());
}
```

### 5.2 场景触发

1. `StartBoxTrigger` 所在物体：`Collider2D` 勾选 `Is Trigger`，`targetScene` 填场景名
2. 目标场景加入 `Build Settings > Scenes In Build`
3. `ExitBoxTrigger` 所在物体：`Collider2D` 勾选 `Is Trigger`
4. 确认触发区域内**至少有一方带 `Rigidbody2D`**（玩家或球进入即可）

## 六、已知限制

1. `Rock.launcher` 在 `Rock.prefab` 中未赋值，碰撞忽略实际尚未生效。
2. 没有任何对外事件（发射、落地、命中），外部无法感知玩法进度。
3. 拖拽使用 `rb.position = 鼠标位置`，是直接传送，不累积速度，所以发射初速完全依赖 `SpringJoint2D` 在 `releaseDelay` 内的回弹。若手感不足，需要改成用位移计算初速度并赋值给 `linearVelocity`。
4. 两个 BoxTrigger 都不区分触发者：球、玩家、任何带 Collider 的物体都会触发。
5. `ExitBoxTrigger` 在编辑器内无效（`Application.Quit()` 只在打包后生效），WebGL 平台同样无效。
